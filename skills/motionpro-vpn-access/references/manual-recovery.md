# GPT 手动恢复：独立于小组件

此路径使用 GPT 的电脑操作能力访问原生 MotionPro 与 MotionProOTP，既不调用 Guard 的登录引擎，也不要求 Guard 的辅助功能权限有效。电脑操作工具本身必须可用，Mac 必须处于已解锁的交互会话。没有可用电脑操作工具时，明确报告限制，不声称已经操作界面。

## 1. 接管前确认状态与预算

1. 运行 `scripts/preflight.py`，确认厂商状态持续为 0/7。若已连接直接验证目标；若正在连接则等待，不启动第二个登录。
2. 记录 Guard 原来是否开启。通过其“断线后自动登录”关闭开关，再用“暂停并退出”退出 Guard；不要停止 MotionPro 服务或其他 VPN。开关在恢复中禁用时等待本次恢复结束。Guard 崩溃而界面无法操作时先确认它确实未运行；不要未经授权强杀进程。
3. 用 `scripts/manual_attempt.py status` 查看预算。该脚本只访问 Guard 的锁和非敏感策略/人工尝试记录，不访问钥匙串。`begin`/`finish` 必须在 Guard 已退出且策略 `enabled=false` 时执行。若它尚在运行，脚本拒绝修改；不能编辑运行中的策略文件与内存状态竞争。
4. 如果 Guard 已不运行但策略仍启用，可运行 `scripts/manual_attempt.py pause`；它取得 Guard 共用锁后保存 `enabled=false`，不启动/结束进程。脚本不自动重新开启 Guard。
5. 每次真正提交登录前才运行 `scripts/manual_attempt.py begin`，保留返回的 `attempt_id`。它先把本次手动提交记入 Guard 的 `submissions`，所以重新启动 Guard 后也会算入同一个滚动小时预算。达到 2 次、失败暂停、未结算尝试或策略损坏时拒绝继续。计数预留后即使没有提交也保留占位，避免意外重试。

Guard 未安装时脚本可以创建最小的禁用策略，但既往手动尝试未知时不要当作“今天没有失败”。结合当前任务内的已知失败和客户端错误；明确锁定、密码被拒绝、已知连续失败 2 次时停止。不要使用脚本清空策略、伪报成功或解除失败暂停。

## 2. 定位正确应用与表单

使用当前电脑操作工具文档中的 API。如果当前环境提供 `mcp__cua_repl`，首次调用遵守它的单入口规则。优先按完整路径选择 `/Applications/MotionPro.app`，避免选择旧解包副本。MotionProOTP 的 bundle ID 为 `net.arraynetworks.MotionProOTP`；iOS 包装应用可能运行在 App Translocation 路径。用应用清单定位本次实际运行实例，不硬编码旧的随机路径。

通过实时 AX 树/截图确认所选配置的网关为用户已授权的目标（BJTU 示例为 `vpn.bjtu.edu.cn`）、账号与当前配置一致。不要硬编码历史账号作为自动覆盖值。每次界面变化后重新读取状态和控件索引，不复用本会话旧编号。

离线时打开所选配置的登录/认证设置表单，保留已记住的账号和静态密码，仅更新 **第二密码 / Password2 / 动态口令**。界面中“连接”可能直接提交已保存的旧第二密码；在尚未找到并更新第二密码之前不要盲点。

优先复用 MotionPro 中已保存的静态密码。它的掩码不是可复制的真实密码。若密码缺失，使用已授权的系统凭据填充途径或请用户直接在 MotionPro 输入；不要把 `security ... -w` 的明文密码输出到对话/日志，不从一个应用取出的密码尝试其他账号或网关。新写解密/注入工具不属于本手动路径的默认步骤。

如果 UI 与已记录版本不同，先检查当前表单和厂商帮助，不能猜键名、修改密文配置或用测试登录探测密码。此技能没有假设固定“编辑”菜单位置，也不包含未经验证的密码注入脚本。

## 3. 读取本次新 OTP 并提交一次

1. 把正确的 MotionProOTP 窗口带到前台，确认令牌站点/绑定身份匹配当前校园 VPN；若它只显示一个已配置令牌且不显示站点，则沿用用户已确认的绑定，不猜测其他令牌。后台读取的计时器可能是缓存。
2. 在曾验证的 macOS 包装版 2.0.6 中，一次性密码标签下有按显示顺序排列的 3 个两位数字按钮，旁边单独的三位数按钮是剩余秒数（0–60）。必须恰好匹配这组结构；不能将所有窗口中的数字拼接。外观变化或多个匹配时停止自动提取，先核实。
3. 至少观察到前台计时器推进后取值；剩余时间至少 25 秒。快过期时等待新一轮，重新读，不使用先前对话中的 OTP。
4. 尽量将 AX 原文与 OTP 保留在工具会话变量中：若当前 CUA 文档支持，`getAXState({emit:false, disableDiffing:true})` 可抑制原文输出，先输出已脱敏的结构用于判断，再从同一份实时结构中解析值。使用 `setValue`/`typeText` 把变量写入已验证的第二密码控件；不要把 OTP 写入脚本文件、剪贴板、技能、报告或 tool title。首次选择应用可能自动返回状态，不额外重复传播。
5. 填好后再次确认网关和剩余有效时间；如已接近过期重新取值。此时预留手动尝试预算，返回表单后按当前界面的“连接/登录”提交 **一次**。等待结果时不重复点击。

## 4. 确认结果、结算与交还

每 10 秒运行只读 preflight，通常最多观察 120 秒。以厂商状态 2/6 为隧道成功；再执行本任务目标的只读可达性验证。

在 Guard 仍退出时结算：

```bash
python3 <skill-root>/scripts/manual_attempt.py finish --attempt-id <begin返回值> --outcome success
# 明确认证失败用 failure；超时/结果不明用 unknown，二者都按失败预算处理。
```

`success` 只记录实际已确认的 VPN 登录成功，不要求服务器业务认证成功；不增加 Guard 的“自动恢复成功”统计。结果不明时再次检查真实隧道，不能未查就提交第二次。脚本重启不丢失 pending 记录；相同结果的结算可重复执行。

- 如果 Guard 原来开启，登录成功后可重新打开它，再恢复开关；共享预算已经包含手动尝试。小组件仍缺权限不影响这次已恢复的 VPN。不得重新开启已被用户主动暂停的功能。
- 失败时先针对已知原因修复（站点、OTP 新鲜度、明确的静态密码缺失）；没有新证据不重试。每小时总计最多 2 次、连续失败 2 次暂停。锁定/账号错误交还用户，不换账号试探。
- macOS 解锁、管理员密码、钥匙串确认由用户在系统界面完成；不要索取 Mac 密码。新增辅助功能权限按当前电脑工具规则确认，不通过 TCC 数据库、关闭 SIP 等方式绕过。
- 立即回到原始校园网/SSH/HPC任务。若原任务含提交或启动，先核对断线前是否已成功，避免重复作业。

## 验证范围

辅助脚本附有纯合成测试，不访问 VPN、OTP 或钥匙串。完整的纯 UI 登录必须在实际需要恢复时根据当前表单执行并验证；单元测试通过、历史自动登录成功或已写好流程都不等于本次手动登录成功。不为验证技能而主动断开现有 VPN。
