# MotionPro 校园网接入与恢复

把网络恢复作为原任务的前置步骤。VPN 恢复后继续原来的服务器/HPC任务，保留原任务的授权与进度。

## 适用环境与边界

- 适用于 macOS 上已配置 MotionPro 的环境。按用户说明和目标路由确定是否必须连接校园 VPN；BJTU 网关示例为 `vpn.bjtu.edu.cn`，实际登录只使用用户已配置并授权的站点。
- 不把所有 SSH、公网 AutoDL、所有私网地址都判为校园网资源。根据用户说明、目标配置及已有成功连接证据逐个判断；目标不明确时先做范围有限的只读诊断。
- 本地阅读代码、校验 manifest、写论文不要求 VPN。开始实时校内查询、SSH、传输或 HPC 操作时才检查。
- 沿用当前用户已给出的登录、凭据保存和 OTP 读取授权；本技能及其示例不自行授予这些权限。访问目标所需的常规登录按当前任务和工具规则处理，不反复询问已明确授权的相同步骤。换账号/网关或扩大权限时重新核对范围。
- 已连接时不主动断开，不用“测试重连”影响现有 SSH/HPC 会话。网络恢复不等于获准启动或取消作业、杀远程进程、删除数据或占用 GPU。

## 首先检查真实连接

运行本技能的只读脚本；将 `<skill-root>` 换成实际技能目录：

```bash
python3 <skill-root>/scripts/preflight.py
```

脚本不读取密码、OTP 或原始日志，不触发登录。它在正确工作目录调用厂商 `vpn_cmdline getstatus`，并输出经过字段白名单过滤的 Guard 状态。厂商命令退出码 `2`/`6` 可能表示连接成功，不能直接当作 shell 错误。

| 结果 | 动作 |
| --- | --- |
| `tunnel_connected_check_target`，厂商状态 2/6 | 保持连接，验证本次目标资源，再继续任务。小组件权限异常不否定现有隧道。 |
| `wait_for_transition`，状态 1/3/4 | 等待当前连接/断开过程，10 秒后检查，通常最多观察 120 秒；不叠加登录。 |
| `recovery_needed`，状态 0/7 | 间隔约 10 秒复核；持续离线约 30 秒后选择恢复路径。 |
| `inspect_client`，状态未知或 5 | 用 MotionPro 界面核实模式/状态；未知状态不能当作已断开直接重启。 |

脚本退出码：0=有校园网隧道；2=离线；3=状态切换中；4=无法确认。`guard.fresh` 仅说明快照时间新，不证明 VPN、目标资源或自动恢复实际正常。

## 选择恢复路径

1. **Guard 正常工作**：快照新、自动恢复开启、静态凭据和辅助功能就绪，且没有失败暂停。给它一个有界的恢复窗口；观察到状态变化时继续等待完成。OTP 窗口在后台可能停止更新，Guard 需要在断线时把它带到前台。
2. **Guard 失效或未就绪**：如快照陈旧、进程停止、权限失效、OTP 一直不刷新、恢复超时，按 [GPT 手动恢复](references/manual-recovery.md) 处理。不要把重装小组件或修复其辅助功能权限作为手动登录的必要前提。
3. **网络恢复后再维护组件**：如任务包含修复组件，读 [部署与组件维护](references/deployment.md)。组件的历史测试结果不是本次恢复成功的证据。

登录必须使用本次新读取、站点匹配且仍有足够有效期的 OTP。手动和自动提交共用每小时最多 2 次的本地预算；不反复点击，不清空计数规避限制。具体协调和计数方法见手动恢复参考。

## 验证目标并回到原任务

- 校内网页：验证用户所需的具体站点可达；登录页、HTTP 响应和业务登录成功分开记录。不要只测公共主页。
- SSH：使用已有的准确主机/端口/跳板配置进行一次有超时的只读连接。按需用 `ssh -o BatchMode=yes -o ConnectTimeout=8 -o ConnectionAttempts=1 <已知别名> true`；不要修改主机密钥信任或遍历无关服务器。
- `Permission denied` 通常是 SSH 认证问题；DNS 失败、TCP 超时、拒绝连接分别诊断。VPN 已连接时，不把所有目标失败都归咎于 VPN。
- HPC：隧道恢复后交回 `$bjtu-hpc` / `$bjtu-hpc-submit`，使用原有账号的集成认证刷新和原生查询。VPN 会话与 HPC 门户 token 是不同层次的认证。
- 若断线前可能已经提交作业或启动进程，先查原有 job ID、receipt、PID 或提交记录；确认远端结果后继续，不能因本地断线重新提交同一个任务。

完成时简报三项：VPN 实时状态、目标资源实际验证结果、原任务是否继续。只有操作系统解锁/验证、缺少可用凭据、明确锁定或目标故障等具体阻塞才交还用户；不把“手动流程已写好”说成“实际登录已验证”。
